New DBOptions::wal_iterator_tail_rotations (default false). When enabled, a WalIterator from GetUpdatesSince() continues across an ordinary WAL rotation after verifying that the next WAL picks up exactly where it left off, instead of ending the run with TryAgain. A consumer tailing the DB no longer has to build a new iterator, and rescan the WAL to find its place, on every rotation. The option is opt-in and transitional: the default is expected to flip to true and the option to be removed in a later release.
