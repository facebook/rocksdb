Added the experimental, non-persisted `DBOptions::track_options_file_number_in_manifest` rollout option (with C and Java bindings). When activated, RocksDB prepares an OPTIONS file number in MANIFEST, durably creates that `OPTIONS-*` file, and then commits the effective file number in MANIFEST. Column-family create/drop commits the configuration snapshot and membership in one record. When disabled, writes retain the legacy highest-numbered-OPTIONS behavior; a higher OPTIONS file without a surviving prepare is recognized as legacy output even if an older commit exists. Persisted-options loading APIs consume the binding, while ordinary `DB::Open` continues to use caller-supplied options and does not depend on the operational snapshot.
