Fixed remote compaction (`CompactionService` / `DB::OpenAndCompact`) ignoring `preclude_last_level_data_seconds` and `preserve_internal_time_seconds`. The worker opens the DB as a secondary, which sets both to 0, so remote compactions wrote recent data to the last level and zeroed sequence numbers inside the preserve window. The primary now sends both values, and the preserve boundary of a bottommost-files compaction, in `CompactionServiceInput`. The fix takes effect when both the primary and the worker run a version with it.
