Fixed wrong reads with `format_version=8` and `ReverseBytewiseComparator`: when a key's user key was a prefix of the previous key in a block (for example a parent key next to a child key such as "parent\x00field"), the block's common key prefix could be longer than that user key, so `Get` and `Seek` could miss live keys and skip newer deletes. SST files already written with this problem are not repaired; rewrite them with a full compaction after upgrading.
