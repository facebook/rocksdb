Added an experimental lazy wide-column read API: `DB::GetEntityLazy()` and `DB::MultiGetEntityLazy()` (see `include/rocksdb/lazy_wide_columns.h`). These return a `LazyWideColumns` / `LazyWideColumnsBatch` whose inline columns are materialized up front but whose blob-backed columns are left as unresolved references; the caller resolves only the columns (and, in a later phase, byte ranges) it needs via `MultiResolve()` / `GetColumn()`, so blobs for columns that are never pulled are never read. Unlike `GetEntity()`, the result may be used after the call returns (it pins the SuperVersion, like an iterator). Requires `max_open_files == -1`. This is an early, evolving feature: the current implementation resolves whole columns (ranges are served by slicing the whole column for now), single column family only, synchronously; partial (byte-range) blob reads, cross-key coalescing, and asynchronous execution are planned follow-ups.
